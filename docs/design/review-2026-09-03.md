# Review of the September waves

Five reviewers, one per area, read main at 102baa4 in throwaway worktrees and
ran what they needed: real two-process pools over a loopback coordinator,
mutations against the suite, and the recipes as shipped. Every item here has a
reproduction or a traced code path. The scout-tier leads that did not survive
expert review are not listed.

The owner's bar for this review: no inaccurate or half-baked implementations,
and nothing that falls apart on a multi-device, multi-host run.

## What holds

Training on a pod works. The lm recipe ran unmodified as a real two-process
pool through `prepare_process`'s environment discovery: join, one global mesh,
sharded train, validation and save, exit 0, bit-identical per-rank metrics.
`build_mesh` spans global devices and the pool tests catch a local-devices
regression. Checkpoints restore across fsdp widths 1 and 8 in both directions,
byte-equal, and across the expert axis (expert 4 to 1 and back, 25 leaves,
0.00e+00). The MoE router matches Mixtral and DeepSeek to 1.79e-07 and
2.38e-07 on weights with equal indices, and matches MaxText's routing where it
cites it. The decoder matches Qwen3, Llama and Gemma 3 at fp32 with every
listed mutation failing parity. The RL surrogates and advantages match verl
and Tunix. The CLIP text tower matches transformers to 1.4e-06 on the tiny
fixture and 1.9e-04 on the real one. generate's cached path equals the
uncached forward. Nothing in the decoder, sampler, LM loss or RL math is
host-dependent; a reviewer drove all four through a real pool and got identical
tokens and an identical CE on both processes.

## What breaks first on a pod, in order

Each of these was reproduced.

1. Resume on a pool fails every time. `trainer.save` stores one
   `dataset_state` blob; orbax writes numpy leaves from process 0 only; every
   rank restores process 0's iterator position; grain rejects the sampler
   (`shard_index=0` in the checkpoint against `shard_index=1` here). Rank 1
   dies, rank 0 follows 30 s later in its first collective. Pool to single
   fails the same way. The committed pool checkpoint tests run in steps mode,
   which never saves `dataset_state`, so they cannot see it.
   `trainer.py:357-379`, `distributed.py:326-330`.
2. `--trainer.checkpoint-fs gcs` crashes at the first save. `checkpoint_path`
   runs `os.path.join`, `abspath` and `makedirs` over the `gs://` URI, so
   orbax receives `<cwd>/gs:/<bucket>/...`. The README, docs/tpu.md and
   tutorial 07 present this flag as the way shards reach a bucket; per-host
   disks cannot share shards, so there is no working shared-storage path.
   `trainer.py:273-279`.
3. Packed-token validation wedges the pod. Documents are strided per process
   and packed independently, so processes pack different window counts (4
   against 5 on a 60-document corpus); any `val_steps_per_epoch` between the
   two leaves one process in a collective forever, and neither process can
   exit. Reproduced on two processes. `dataloaders.py:819-845`.
4. Validation swallows every exception per rank, so a local failure on one
   host becomes a hang on the others instead of an error. Both
   `validation_loop` implementations. `trainer.py:400-432`,
   `objective_trainer.py:304-385`.
5. Three of the eight `distributed` tests are red at HEAD: the expert-axis
   merge added `'expert': 1` to the mesh shape and the pool tests assert the
   old dict. The mesh-coverage guards behind them never execute. CI runs
   `-m 'not network'`, which includes them. `tests/test_multiprocess.py:201,
   213, 368`.
6. `resume_last_run` resolves on process 0 only: rank 0 resumes from artifact
   weights while the others train from scratch. `trainer.py:127-150`.
7. Default run names embed a per-process wall-clock second, so ranks that
   start a second apart write to different checkpoint directories.
   `recipes/*/train.py`.
8. Tutorial 07's pod command composes to `python python recipes/lm/train.py`
   and cannot start. `tutorials/07` cell 16 against `cli/tpu.py:670`.

## What breaks on one host

1. A default diffusion run dies at startup: `dew/eval/images.py` imports
   `FlaxCLIPModel`, which transformers 5 removed, and the recipe defaults
   `val_metrics=['clip']`. The encoder was vendored; the metric was not.
2. `HFAudioEncoder.from_modelname` imports `FlaxAutoModel`, also removed, so
   audio conditioning cannot be constructed. `inputs/encoders.py:145-147`.
3. With an autoencoder and no explicit `native_resolution`, the trainer
   multiplies the pixel shape by the downscale factor a second time, so
   tutorial 03 validated at 1024x1024 from a model trained at 16x16 latents
   (18 GB of XLA arguments on the 4080). The recipe passes the resolution and
   is unaffected. `objective_trainer.py:127-131`.
4. `--trainer.expert-size N` parses, is documented, and is dropped by all
   three recipes: an expert-parallel run trains with every expert replicated.
   `recipes/lm/train.py:281` and siblings.
5. A relative `--trainer.load-from-checkpoint` fails inside orbax; `load`
   does not `abspath` where `checkpoint_path` and `load_from_checkpoint` do.
   Tutorial 07 works around it with `.resolve()`. `trainer.py:311-329`.
6. Validation-pass augmentation is nondeterministic: the shared albumentations
   pipeline is mutated per call and executed from grain's prefetch thread
   pool. 33 to 84 of 256 records differed in pixels between thread counts.
   The training stream is unaffected. `dataloaders.py:337-358`,
   `sources/images.py:70-80`.
7. A validation record's augmentation and caption depend on the process
   count, because the per-record rng is keyed by the local index after the
   `[p::n]` slice. `dataloaders.py:349-354`.
8. The notebook harness `tools/run_notebooks.py` has never executed a
   notebook: it fails on `str.name` before papermill runs, lists 01 to 04
   only, injects no parameters, and 01 carries an unconditional
   `pip install jax[cuda12]==0.4.28` cell.

## Half-baked, by area

MoE: only the Mixtral-shape router is reachable. The DeepSeek options
(sigmoid, aux-loss-free bias, group limit, scaling, shared expert) are
parity-tested and cannot be built through any model path; `hf_decoders` has
no MoE handling. `implementation='auto'` raises where the attention seam
resolves it, so the tokamax branch is dead code. Expert parallelism replicates
every dense parameter, moment and EMA copy across the expert axis. On CPU and
default GPU lowering, `ragged_dot` is a masked dense expansion.

LM: `val/perplexity` is exp of the unweighted mean over batches of each
batch's token-weighted CE, which is exact only when every batch counts the
same number of targets; the packed loader guarantees it does not. A batch
with no counted target reports CE 0.0 and drags perplexity toward 1. RMSNorm
uses Gemma's cast order for every family where Llama and Qwen3 multiply after
the cast; invisible at fp32, where every fixture runs. The bf16 decoder
tolerance holds for gemma3-tiny (5.7e-02) and not for llama-tiny (2.01e-01,
argmax differs). The `pretrained=` path bakes the whole checkpoint into the
jitted init as constants. The CLIP parity note blames a rearrangement that is
bitwise identical; the 1.9e-04 residue is unexplained.

Data: the whole-batches-per-process guarantee holds only through
`load_data`; the tutorials call the factories directly with a `val_count`
that can strand a process. The streaming loader replaced silent zeros with a
silent infinite wait when every fetch fails. `_SourceSlice.__repr__` cannot
tell two same-length datasets apart, so a resumed run can restore the wrong
one's position.

Docs: README says the trainer writes a checkpoint every epoch; it writes one
when the loss improves. README describes a submodule that no longer exists.
Tutorials 05 and 07 say 42M parameters for a 50.5M model. Tutorial 06
explains its probe design with a bug fix/val-split already removed. Tutorial
01 carries 8.4 MB of outputs against the CONTRIBUTING rule, and the README
links it for its figures.

## Test gaps that let plausible bugs through

Each survived the whole suite as a mutation.

- Accumulating the MoE expert combine in bf16 instead of fp32.
- Deleting `WEIGHT_SUM_EPSILON` (the all-zero top-k case has no test).
- Dropping GAE's passthrough term (`advantage = candidate * keep_t`), which
  changes real answers; verl's own loop disagrees with the mutant.
- Adding `1e-8` to `token_mean`'s denominator.
- Hardcoding the q/k-norm epsilon.
- Doing the tied head einsum in bf16 instead of fp32.
- Swapping RMSNorm's cast and scale order.
- A restore that drops or transposes the expert leading dimension.
- Wrong Muon dimension numbers under expert sharding.
- A regression that makes decode quadratic again.
- Any CLIP degradation up to 70x on the tiny fixture (1.43e-06 against 1e-4).

## Fix plan

Wave A, the pod: per-process iterator state (allgather padded rows, each rank
restores its own, record the process count and refuse a mismatch with the
reason), `checkpoint_path` branches on scheme and hands `gs://` to orbax
verbatim, per-process validation lengths agreed before the loop (allgather
the batch count, run the minimum), validation exceptions propagate,
`resume_last_run` resolved on process 0 and broadcast, run names taken from a
broadcast timestamp, the three pool tests expect the expert key, and a
fit-mode pool-to-pool and pool-to-single resume test with a real
`ShardByJaxProcess` loader.

Wave B, single host: the CLIP metric on the vendored tower, the audio encoder
on a vendored or removed path (removed unless a caller exists),
`native_resolution` default without the second multiply plus a test with an
autoencoder, `expert_size` plumbed through the three recipes and the
benchmark, `load` abspaths, a thread-local augmentation pipeline with a
threaded-versus-serial pixel test, validation rng keyed by global index.

Wave C, the LM numerics: perplexity as exp of the token-weighted mean over
the whole pass, no 0.0 for an empty batch, RMSNorm order per family, the
bf16 tolerance stated per family, the CLIP parity note corrected, and the
eleven mutation tests above.

Wave D, MoE reach: the DeepSeek router options through CausalTransformer and
the HF config translation, `implementation='auto'`, an expert-parallel
benchmark row, the expert-axis restore test.

Wave E, docs and the harness: the eight corrections above, and a harness
that runs.
