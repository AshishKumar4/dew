# Data-pipeline migration receipts

These scripts produced the evidence for the move to `Pipeline` recipes and for the published decision data: what the old loaders read, that the decision mix fits as the old eager path fitted it, and how the producer's objects were verified. Each one is pinned to the revisions it names, so it reproduces that evidence and is not a maintained tool or a CI gate. Run them from the repository root, with Dew installed from the checkout. Their `r2://` pins name Dew's own data bucket, which public Dew does not reach. Reading them needs the dew-ops `r2` filesystem adapter, and the publishing steps need write access through it.

| File | Baseline | Purpose | Reproduction |
| --- | --- | --- | --- |
| `data_oracle.py`, `data_oracle_legacy.py` | Dew `66beb5305` | Records what each old loader read from synthetic records, at 0 and 2 workers and 1 and 2 shares. `data_oracle.py` downloads the baseline and runs `data_oracle_legacy.py` inside it. The gzipped output is `tests/fixtures/golden/loaders-66beb5305.json.gz`, which `tests/test_pipeline_golden.py` reads. | `python tools/measurements/data-pipeline/data_oracle.py --output loaders-66beb5305.json` |
| `decision_data_oracle.py` | Dew `66beb5305`, tokenizer `Qwen/Qwen3.5-2B` at `15852e8c` | Compares the accepted and scored row identities of one mix-v3 corpus under the baseline's eager fit and under the pipeline's `Fit`. | `python tools/measurements/data-pipeline/decision_data_oracle.py --corpus banking77 --output banking77.json` |
| `decision-mix-v3.json` | mix-v3 manifest `4e9da7aa` | A summary of `decision_data_oracle.py` reports for the 35 mix-v3 corpora: total rows and drops, `equal: true`, and each corpus report's SHA-256. No test reads it. | Run `decision_data_oracle.py` once per corpus. |
| `decision_metadata.py` | mix-v3 shards | Derives each set's slot bounds from the immutable shards and publishes them as a descriptor, without rewriting data. The producer now writes these bounds itself; `tests/test_decision_sources.py` runs this script on a local mixture. | `python tools/measurements/data-pipeline/decision_metadata.py --set banking77`, then `--publish` |
| `decision_versions.py` | descriptor `a4fce93c` | Proves each object's stored version against its canonical digest and publishes a descriptor that carries the versions. The version it records is the filesystem's `ukey`. | `python tools/measurements/data-pipeline/decision_versions.py --set banking77`, then `--publish` |
| `build_decision_data.py` | `decision-index` at `9eb2dbe2`, index SHA-256 `553367f3` | Rebuilds the decision evaluation overlap index on remote compute and publishes its hashes. | `python tools/measurements/data-pipeline/build_decision_data.py --work WORK_DIR` |
| `decision_budget_session.py` | attribution tools at `b420100f` | Runs `tools/benchmark_decision_budgets.py` for the row and token-budget arms on one A100 VM, then profiles and attributes both. | `python tools/measurements/data-pipeline/decision_budget_session.py --output SESSION_DIR` (`--smoke` for a short run) |
| `token_budget_gold.py` | tokenizer `Qwen/Qwen3.5-2B` at `15852e8c` | Reads the real mix-v3 token-budget path on armada and reports the batch shapes it saw, request counts and an exact resume. | `python tools/measurements/data-pipeline/token_budget_gold.py --output token-budget.json` |
